# Матрица выбора скиллов

| Запрос | Скиллы |
|---|---|
| Проверить механику атаки | `effect-audit` |
| Проверить визуал атаки | `effect-visual-audit` |
| Проверить принятие решений врагом | `enemy-ai-audit` |
| Проверить сочетание атак | `effect-interaction-audit`, `effect-audit` |
| Проверить сложность и числа | `combat-balance-audit` |
| Проверить читаемость результата действий | `combat-ux-feedback-audit`, `effect-visual-audit` |
| Составить/провести боевые тесты | `combat-playtest-qa-audit` + профильный скилл |
| Оценить новую способность | `enemy-effect-design-audit` |
| Комплексный анализ | `combat-audit-orchestrator` + `audit-run-memory` |
| Продолжить тот же большой/повторяющийся аудит | `audit-run-memory` + профильные скиллы |
| Проверить, какие атаки уже просмотрены/исправлены | `audit-run-memory` |

Координатор должен выбирать только необходимый набор проверок, не запускать всё автоматически.


## Память запросов — обязательный слой

`audit-run-memory` применяется к каждому запросу и координирует последовательные проходы. Он создаёт отдельный JSON на активный запрос, перечитывает его на каждом проходе, сравнивает стабильные ID и fingerprints, пропускает неизменившиеся элементы и после подтверждённого полного прохода сохраняет итоговый Markdown-отчёт и удаляет только временный JSON.
