# Полная система аудита боевых эффектов и противников

**Проект:** «Дурак: Путь Туза»  
**Платформа скиллов:** OpenCode  
**Состав:** 10 скиллов + общие справочники и протокол памяти запросов  
**Режим по умолчанию:** read-only, без правок кода и ассетов.

## Состав комплекта

| ID | Скилл | Для чего |
|---|---|---|
| `effect-audit` | Механический аудит эффектов | Как работает способность, триггеры, последствия, контригра, технические края |
| `effect-visual-audit` | Визуальный аудит эффектов | Внешний вид, анимация, телеграф, читаемость и визуальная обратная связь |
| `enemy-ai-audit` | Аудит ИИ противников | Выбор целей, приоритеты, состояния, позиционирование и переходы |
| `effect-interaction-audit` | Аудит взаимодействий | Комбинации, stacking, цепочки, наложения и нечестные комбинации |
| `combat-balance-audit` | Аудит баланса | Урон, HP, скорость, cooldown, окна реакции и давление |
| `combat-ux-feedback-audit` | Аудит боевого UX | Ввод, обратная связь, звук, камера, HUD и понятность исходов |
| `combat-playtest-qa-audit` | Плейтест и QA | Воспроизводимые тесты, крайние случаи, регрессии и эксплойты |
| `enemy-effect-design-audit` | Аудит дизайна | Качество идеи, роль врага, выбор игрока, контригра и уникальность |
| `combat-audit-orchestrator` | Координатор | Маршрутизация проверок и общий отчёт |
| `audit-run-memory` | Память запросов | Отдельный файл на запрос, пропуск уже проверенных объектов, продолжение следующими порциями и финальная очистка временного файла |

## Установка

В ZIP сохранена структура:

```text
.opencode/
  skills/
    effect-audit/SKILL.md
    effect-visual-audit/SKILL.md
    enemy-ai-audit/SKILL.md
    effect-interaction-audit/SKILL.md
    combat-balance-audit/SKILL.md
    combat-ux-feedback-audit/SKILL.md
    combat-playtest-qa-audit/SKILL.md
    enemy-effect-design-audit/SKILL.md
    combat-audit-orchestrator/SKILL.md
  references/
    combat-audit/
      PROJECT_AUDIT_CONTRACT.md
      JOURNAL_MAP.md
      REPORT_SCHEMA.md
      RUN_MEMORY_PROTOCOL.md
```

1. Сделай резервную копию или проверь Git проекта.
2. Распакуй архив во временную папку.
3. Скопируй папку `.opencode/skills/` в корень проекта и **объедини** её с существующей `.opencode/skills/`. Не удаляй свои старые скиллы.
4. Скопируй `.opencode/references/combat-audit/` в соответствующий путь проекта.
5. Если папки/скиллы с такими ID уже существуют, сначала сравни файлы; не перезаписывай свои версии вслепую.
6. Перезапусти OpenCode или открой новую сессию в корне проекта, чтобы он обнаружил скиллы.

Официальный формат OpenCode: один каталог на скилл, `SKILL.md` внутри; ID определяется названием каталога. См. https://opencode.ai/docs/skills/.

## Быстрый запуск

Главный координатор:

```text
@combat-audit-orchestrator Проведи полный аудит 7♠ как самостоятельного противника. Не смешивай его с групповым поведением.
```

Аудит эффекта:

```text
@effect-audit Проверь прыжок 7♠ за спину: механику, телеграф, последствия и контригру.
@effect-visual-audit Проверь, понятно ли игроку, куда Семёрка собирается прыгнуть.
@enemy-ai-audit Проверь выбор момента и позиции для прыжка 7♠.
```

Проверка комбинации:

```text
@effect-interaction-audit Проверь сочетание ямы 7♠ и веера 8♠. Найди ситуации, где игрок теряет все варианты выхода.
```

Баланс и тестирование:

```text
@combat-balance-audit Проверь окно реакции на прыжок 7♠ по фактическим параметрам.
@combat-playtest-qa-audit Составь воспроизводимые тесты для прыжка 7♠ и его уязвимого состояния после промаха.
```

## Общая дисциплина

- Журнал E/P/H/M/L — источник контекста, а не повод придумывать отсутствующие механики.
- Факты реализации отделяются от решений пользователя, гипотез и предложений.
- Текущие параметры всегда перепроверяются в активных исходниках и конфигурации.
- Нельзя заявлять о проверенном визуале/звуке, если соответствующего материала не было.
- Аудит не меняет код, JSON, настройки, сохранения или ассеты.
- Каждый пункт реализации требует отдельного `АПРУВ` пользователя.
- `P-001` и т. п. — номера принципов журнала; серьёзность дефекта маркируется `S0–S3`.

## Качество и ограничения

Этот пакет содержит инструкции для анализа, а не готовые автоматические тесты и не гарантированный доступ ко всем файлам/скриншотам/видео. Для достоверного аудита OpenCode должен иметь доступ к активному проекту, журналам и, когда это требуется, к запущенной сборке или видеозаписи. Если доступа нет, скилл должен отметить пробел, а не имитировать проверку.


## Память повторяющихся и больших аудитов

Скилл `audit-run-memory` обязателен для каждого аудиторского запроса. Он создаёт отдельный файл `.opencode/audit-memory/active/<request-id>.json`, сохраняет исходную формулировку запроса, список найденных объектов, результаты анализа, fingerprints и статус исправлений. Перед **каждым** проходом файл перечитывается с диска, а исходная область сканируется заново.

По умолчанию обрабатывается 10 уникальных объектов за один проход. Например, для 100 атак первый вызов проверит 10 и сохранит 90 ожидающих. Повтор того же запроса перечитает файл, пропустит прежние 10 и проверит следующие 10. Изменившийся fingerprint возвращает объект на повторный аудит.

Запрос считается завершённым только после полного контрольного сканирования, в котором не осталось новых, изменившихся, ожидающих и блокированных элементов, а обнаружены только уже учтённые повторы. После этого итог сохраняется в `.opencode/audit-memory/reports/<request-id>.md`, отчёт перечитывается для проверки, и удаляется только временный JSON данного запроса. Итоговый отчёт остаётся постоянной памятью о просмотренном, проанализированном и действительно исправленном.

Незавершённые и заблокированные запросы сохраняют активный JSON. Если файловая память недоступна, скиллы должны честно сообщить об этом и не заявлять, что прогресс сохранён.
